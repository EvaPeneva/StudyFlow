## 2. Какво реално реализирахме?

### 2.1. Потребителски интерфейс

Подготвихме и стартирахме работещ прототип на StudyFlow с три основни изгледа:

1. **Табло** - показва общия брой задачи, предстоящите и завършените.
2. **Моите задачи** - позволява добавяне, разглеждане, търсене и филтриране на задачи.
3. **Календар** - начален изглед за организиране на учебните задачи по дати.

Проверихме навигацията между Табло и Моите задачи.

Интерфейсът е разработен с HTML5, CSS3 и JavaScript.

### 2.2. Двуезичност BG/EN

Приложението поддържа български и английски език.

Преводите са организирани в отделни JavaScript файлове:

- `src/locales/bg.js`
- `src/locales/en.js`

Българският език се зарежда по подразбиране.

Проверихме превключването между BG и EN. След смяната на езика двете съществуващи задачи останаха налични.

### 2.3. База данни в Supabase

Създадохме реален проект StudyFlow в Supabase.

Чрез SQL файла `database/schema.sql` създадохме пет свързани таблици:

- `profiles` - съхранява потребителските профили.
- `subjects` - съхранява учебните предмети.
- `tasks` - съхранява учебните задачи.
- `reminders` - предназначена за напомняния.
- `task_tags` - предназначена за етикети към задачите.

Таблиците имат първични и външни ключове, подходящи типове данни и ограничения.

Настроихме RLS политики, които ограничават достъпа на потребителите до собствените им записи.

Създадохме тестов потребител, след което автоматично се появи запис в таблицата `profiles`.

Добавихме три примерни учебни предмета:

1. Математика
2. Български език
3. История

### 2.4. JavaScript и работа с реални данни

Свързахме StudyFlow със Supabase чрез JavaScript и Supabase Auth.

Проверихме успешен вход с тестов потребител.

Приложението зареди съществуващата задача „Домашно по математика“ от базата данни.

След това добавихме нова задача „Домашно по история“ директно през уеб приложението.

Проверихме, че новата задача присъства и в Supabase Table Editor.

По този начин потвърдихме реално четене и записване на информация в базата данни.

## 4. Какви проблеми срещнахме?

При качването на файловете в GitHub част от тях първоначално бяха поставени в неправилни папки.

Например `supabase-config.js` се намираше в `src/locales`, вместо директно в `src`.

Поправихме местоположението чрез GitHub редактора и запазихме промяната с отделен commit.

Срещнахме затруднения и при добавянето на свързани записи в Supabase, защото трябваше да изберем правилните стойности за `user_id` и `subject_id`.

След проверка на връзките между таблиците успяхме да добавим примерните предмети и задачи.
