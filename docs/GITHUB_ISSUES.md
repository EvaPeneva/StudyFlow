# GitHub Issues — 12 предложени задачи за създаване

**Защо 12?** Общото задание иска поне 6, но индивидуалното за StudyFlow иска поне 12. Подготвяме 12 за по-сигурно покриване на условията. **Този файл не създава автоматично GitHub Issues — трябва да ги добавите в истинското хранилище.**

## Ученик 1 — интерфейс и UX

1. **[Stage 1] Създаване на README и начална frontend структура** — файлове `index.html`, `style.css`, `script.js`; критерий: могат да се отворят чрез локален сървър.
2. **[Stage 1] Дизайн на Dashboard** — макет, лого, меню, броячи; критерий: файл `design/01_dashboard.png`.
3. **[Stage 1] Дизайн на Tasks screen** — макет на задачи и формуляр; критерий: файл `design/02_tasks.png`.
4. **[Stage 1] Навигация между екрани** — бутони Табло/Задачи/Календар; критерий: менюто сменя екрана.
5. **[Stage 1] Двуезичен интерфейс BG/EN** — отделни езикови обекти; критерий: превежда основните текстове без загуба на задачите.
6. **[Stage 2] Адаптивен дизайн за телефони** — критерий: тесен екран без отрязани бутони и форми.

## Ученик 2 — данни, логика и тестове

7. **[Stage 1] Проучване на три сходни приложения** — MyStudyLife/Todoist/Google Calendar; критерий: `docs/RESEARCH.md` с линкове.
8. **[Stage 1] Модел на данните и ER диаграма** — profiles, subjects, tasks, reminders, task_tags; критерий: PNG + Mermaid.
9. **[Stage 1] Описание на алгоритъма и два подхода** — Weighted Score срещу Earliest Deadline First; критерий: 3 ръчни примера.
10. **[Stage 1] Планиране на функционалности и потребителски истории** — критерий: `PROJECT_PLAN.md` и `PRODUCT_SPEC.md`.
11. **[Stage 2] Създаване на Supabase schema и RLS** — критерий: минимум 3 свързани таблици, тестови данни, проверка на достъпа.
12. **[Stage 3] CRUD операции от JavaScript към Supabase** — критерий: задачи се създават, прочитат, редактират и изтриват от реалната база.

## Как да ги въведете

1. Влезте в общото GitHub repository → **Issues** → **New issue**.
2. Копирайте заглавието и описанието на всяка от 12-те задачи.
3. В полето **Assignees** изберете участника, посочен по-горе (можете да коригирате разпределението според действителната работа).
4. Добавете етикети `stage-1`, `stage-2`, `stage-3` и, ако искате, `frontend`, `database`, `docs`.
5. Създайте **GitHub Project** (табло) с колони `Todo`, `In progress`, `Done` и добавете Issues в него.
6. Местете в `Done` само реално свършените задачи. Свързвайте commit-и и Issues, ако знаете как.
