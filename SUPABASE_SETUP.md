# StudyFlow · Етап 2 · Настройка на Supabase

**Тази настройка задължително се изпълнява от Ева и Михаела в собствения им Supabase проект.** Подготвеният ZIP не създава база автоматично.

## 1. Проект и таблици

1. Отворете https://supabase.com/dashboard → **New project**. Изберете организация, например име `studyflow-school-demo`, и силна парола за базата. **НЕ публикувайте паролата.**
2. След създаването отворете **SQL Editor → New query**.
3. Във VS Code отворете `database/schema.sql`, копирайте целия код и го поставете в SQL Editor.
4. Натиснете **Run**. При грешка спрете, запазете текста на грешката и потърсете причина, вместо да изключвате RLS.
5. Отворете **Database → Tables / Table Editor**. Трябва да има **5 таблици**: `profiles`, `subjects`, `tasks`, `reminders`, `task_tags`.
6. Отворете **Database → Policies**, за да видите RLS политиките. За всяка таблица трябва да има ограничение по собственик (`auth.uid()`).

**Защо 5 вместо 3?** Етап 2 изисква минимум 3. Запазваме модела на Етап 1 с допълнителните 2 таблици за бъдещи напомняния и етикети. В Етап 2 реално тестваме `profiles`, `subjects`, `tasks`.

## 2. Публични настройки (без тайни)

1. В Supabase намерете **Project URL** и **Publishable key** (в **Connect**, или **Project Settings → API Keys** според изгледа).
2. Отворете `src/supabase-config.js` и заместете ДВАТА примерни текста:

```js
export const SUPABASE_URL = 'https://ВАШИЯТ-ПРОЕКТ.supabase.co';
export const SUPABASE_PUBLISHABLE_KEY = 'sb_publishable_ВАШИЯТ_ПУБЛИЧЕН_КЛЮЧ';
```

Ако таблото показва legacy `anon` key, може да се използва само ако документацията на проекта и настроените RLS политики го позволяват. Предпочитайте **publishable key**. **Никога не използвайте `secret` или `service_role` ключ в уеб приложение или GitHub.**

## 3. Вход и тестови данни

1. Стартирайте сайта през **Live Server**. При работеща база входът се показва след натискане на **Вход / Регистрация**.
2. Създайте тестов акаунт. Използвайте адрес, който можете да потвърдите, и НЕ използвайте чужда лична информация. Ако `Confirm email` е включен в Supabase Auth, потвърдете имейла и след това натиснете Вход.
3. Ако регистрацията не е разрешена, проверете **Authentication → Providers → Email** и настройките за регистрация. Не заобикаляйте потвърждение на имейл; използвайте нормален тестов акаунт.
4. След вход статусът трябва да е **„Supabase • свързан“**. Ако пише „Локално демо“, записът **не е** в базата.
5. Отворете **Моите задачи → Зареди примерни данни** (веднъж). Този бутон добавя **3 предмета и 3 примерни задачи** за влезлия потребител.
6. Добавете нов предмет, след това нова задача. Натиснете **↻ Обнови от базата**; задачата трябва да остане.
7. В Supabase Table Editor проверете `profiles`, `subjects` и `tasks`. Данните трябва да имат свързани `user_id` и `subject_id`. В `tasks` трябва да има поне 3 реда за тестовия акаунт.
8. Отбележете една задача като готова и проверете в Table Editor `is_completed=true`. Изтрийте друга и проверете, че редът изчезва.

## 4. Сигурност / RLS

- `profiles.id` е FK към `auth.users.id`.
- `subjects.user_id` и `tasks.user_id` са FK към `profiles.id`.
- `tasks(subject_id,user_id)` е комбиниран FK към `subjects(id,user_id)`, което не позволява използване на чужд предмет.
- RLS разрешава достъп само когато `user_id = auth.uid()` (или `profiles.id = auth.uid()`).
- Проверка с **втори отделен тестов акаунт**: след вход задачите от първия не трябва да се виждат; чужд идентификатор не трябва да може да се редактира. Не публикувайте идентификатори, имейли, пароли или токени.

## 5. Какви доказателства да предадете

**Истински снимки от вашия проект** (не могат да бъдат генерирани предварително):

- Supabase Table Editor: списък на петте таблици (поне три се виждат).
- `subjects`: тестови редове (само измислени имена).
- `tasks`: примерни редове и `subject_id` (замъглете идентификатори, ако не са нужни).
- `Database → Policies` (показва, че RLS е включен).

Не снимайте табове с чувствителни ключове или пароли.

## 6. Ако не работи

- „Invalid API key“ → проверете publishable key.
- „Failed to fetch“ → адрес, интернет, CDN, публикуван origin.
- „Permission denied“ / празни заявки → проверете влизането, профила и RLS политиките; **не изключвайте RLS**.
- Не виждате запис след добавяне → проверете статус „Supabase • свързан“; „Локално демо“ не изпраща заявки.
